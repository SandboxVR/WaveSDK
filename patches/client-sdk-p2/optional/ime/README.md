# IME lifecycle donor

`setContext` stores the application Context. `onCreate` installs a generation-scoped retry. `onDestroy`/`release` close that generation, cancel the exact retry, detach callback/parameter/Context owners, clear state, and then unregister remote callbacks, unlink death recipients, and unbind outside the lifecycle monitor. A successful bind is unbound even when close races its return before a connection arrives.

Each manager binding has a distinct callback and each IME service registration has a serial. Retired bindings/services cannot switch or complete the current keyboard. An accepted pending bind waits for its connection callbacks without idle polling. Handshake failure rolls back partially published state and ambiguous callback registration, including a locally linked death recipient whose `getApi` call failed before publication. Failure/disconnect/death recovery allows three 500 ms delayed retries. Successful service registration resets the budget; explicit `onCreate` after close starts a new budget. Exhaustion leaves automatic recovery stopped until an explicit lifecycle restart.

Binder calls, Context binding/unbinding, and application callbacks run outside the owner monitor. Request admission captures lifecycle/request identity, so returning old show/restore calls cannot revive callbacks in a replacement lifecycle. Active callback/parameter retention follows the original API: repeat submits, no-hide mode, `restoreShowKeyboard`, and explicit `requestIMECompleted` after `showKeyboardDefault` remain supported. Owners are cleared at lifecycle teardown. Unavailable service and `RemoteException` still return zero from default show routes, and unsupported no-editor mode falls back to the original keyboard route.

No compile stubs are needed for this group. The manifest adds six package-private helper classes, nine default-initialized fields, and replaces/adds 28 methods. See the parent optional README for actual grafted-JAR tests and build commands.
