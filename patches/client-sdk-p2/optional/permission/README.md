# Permission lifecycle donor

An Activity remains available during the active UI lifecycle. Application Context owns all service bindings and receiver registrations. `release` closes the generation, detaches Activity/PackageManager/user callback/request references, cancels queued retries and OS USB request ownership, interrupts config/notification workers, and then closes registrations outside the owner monitor. Late bind/receiver acceptance is released exactly once by the corresponding registration object.

VR permission and USB requests use captured generation/request identities for sending, callbacks, failure completion, and disconnect completion. Permission reply lengths/names are checked before indexing, reordered results map to the original request order, and unrelated/duplicate/stale replies cannot consume a new request. USB service replies require the expected device. Ordinary completion clears the request callback; the USB hotplug subscription remains active until release, matching the ongoing subscription behavior of the original API.

2D USB requests own a separate receiver and a unique PendingIntent action per request. A canceled or superseded OS response cannot alias a new request or replacement Activity's callback. The result must match the pending device; completion and setup failure retire the receiver, cancel the OS token, and release the pending latch. Enumeration also carries its original lifecycle/subscription identity through the 2D/VR route selection.

Config and notification work keep their original background execution and retry/delay policy. Binder calls and application callbacks execute outside lifecycle monitors. 2D application permission requests retain the original `Activity.requestPermissions(..., 1)` contract, including the original absence of a Unity permission callback on that route. The original private synchronized USB enumeration entry point is replaced with a snapshot-based implementation; its manifest explicitly takes donor access flags to remove the method monitor while retaining private access.

The compile-only `R` donor declares non-final fields so generated bytecode references the consuming app's resource fields. It is excluded from the manifest. The manifest adds seven package-private helper classes, thirteen default-initialized fields, and replaces/adds 44 methods. See the parent optional README for actual grafted-JAR tests and build commands.
